# 消融案例：指导差异与结果差异的解释链

本轮依据用户新增标准重新核查。它取代 [上一轮优势选例建议](ablation-reselection-20261105.md) 中对 A5、A2、A3 的消融展示推荐；不更改原始事实，也不撤销已有版式参考。

## 判断标准

必须分开两条链：

1. agent 的错误理解 → 错误动作或漏执行 → 任务失败。
2. 指导中可辨认的错误、遗漏或修正 → agent 相应的判断/行动 → 结果差异。

上一轮主要满足第一条，却用它推荐解释指导来源/结构优势的案例。正确或语义等价的指导一成一败，不能仅靠把失败思考高亮就补齐第二条。自然语言 `recovery_check` 与系统局部检查也是不同对象；只有真实发生的检查及后续决策才能支持核验字段的机制解释。

## 后备候选

预约 03 (`booking_and_scheduling_11_4`) 的“同日预约标记”是目前更有解释力的局部候选：用户要求 same-day sick visit；Teacher 指导明确写入 `is_same_day_booking=1`，Student/Teacher freeform 指导均未提该字段；实际创建相同患者、时段和就诊类型的调用分别带 1 / 省略 / 省略，字段默认 0，最终新记录 BK-20 为 1 / 0 / 0。协调者已独立读取完整指导、任务和实际调用，并检查各分支 final.db 中的新记录，未把患者原有预约混作本次结果。

进一步检查发现决定性反证：工具 schema 将 `is_same_day_booking` 定义为“1 if booked on same day as appointment date”，Teacher 实际工具返回和 final.db 中 BK-20 的 booked_at 是 **2026-11-03 12:31:08.850122**，但所选 SL-3004 的 start_datetime 是 **2026-02-03 08:45:00**。不是缺少日期证据，而是记录本身不满足字段语义。协调者已独立核对 msg17、BookingCreateRequest 定义及两张数据库表。

因此撤回初步的局部展示推荐：这条指导—参数—状态链比现有三例清楚，但尚不满足 Ours 语义正确的首要要求。将其列为优先修复的研究候选，先对齐任务日期、环境时间和检查规则，再重跑所有设置；不能编辑旧结果或只截取字段来掩盖时间矛盾。该候选的执行推理也未记录，未来展示不能补写 agent 动机。

其他后备及精确来源见 [后备审查](cases/ablation/causal-audit-reserves-20261105.md)。当前审核范围内，**没有可直接加入并满足新标准的替代案例**。01 定价有日期/规则矛盾，02 扩大了用户时间范围，61 的 Ours 推理仍不清楚，R02A 也有指导分析错误且其他分支最终恢复成功。

## 工作流更新与状态

`steerdistill-case-editorial` 已补入上述第二条证据链、相同指导替代运行检查，以及 `recovery_check` 执行证据要求；限定适用于解释指导机制的消融，不扩大为所有恢复/失败案例的门槛。技能结构验证通过。

本轮仅核查、记录和提出取舍建议。案例页面及目录尚未改动；未生成新运行，未发布网站。建议暂停将三个现有案例用于解释指导来源/结构优势，并先修复预约候选的环境语义后再考虑补充。
