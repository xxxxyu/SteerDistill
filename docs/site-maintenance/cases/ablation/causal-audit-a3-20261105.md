# A3：指导内容与执行差异复核

2026-11-05。独立核验，只修改本审查记录，不改页面。依据实际指导、生成分析、注入请求、完整执行思考和状态；旧审查结论只用作定位线索。

## 结论

**A3 不适合作为“Teacher 指导内容优于其他来源/格式”的消融精选。** 加油任务和执行失败都清楚，但各设置给出的关键操作一致且正确。失败 agent 不执行已经明确要求的操作，不能归因于指导缺少该操作。当前默认 Teacher 成功 vs GPT 失败尤其容易误导：GPT 完整请求只更换 seed 就有成功/失败两种结果。

把失败原因解释为“agent 把换算当成完成”是有原文支撑的；把这种错误再归因于 GPT 指导不够好，则没有具体内容差异支撑。两者不应混同。

## GPT 对比：执行波动的直接证据

`B/trial-history/trials/external_structured/guide-0/seed-71782927/turn-000/request.json` 与 `.../seed-71782928/turn-000/request.json` 顶层逐字段比较，**唯一差异为 seed**。模型、温度 0.6、top_p、top_k、完整 messages（包括注入指导）、其他生成参数均一致。identity 中 context/state/guidance hashes 也相同。

- 927 的完整思考明确“next step ... fillFuelTank ... 10.04”，实际调用并得到 fuelLevel 20.04；state/response checks 通过。
- 928 的完整思考在四舍五入后写“Since the task is done”，直接回复准备好了加油量；没有调用，油量仍为 10.0。

完整指导本来已针对这一错误写了“do not ... claim completion before this call succeeds”。失败不是指导遗漏“必须执行”或核验规则；它是没有遵循已提供的正确要求。将 928 换成默认失败对照突出不了 Teacher 内容优势。

## Teacher 内部 guide-0 → guide-1 是否更合适

**有一个同 seed、同起点的失败→成功对照，但不足以构成清楚的指导改进故事。** 两个 seed-71782927 的 request 除 messages 外其他字段一致；messages[1:] 完全一致，系统消息的差异为注入的四字段指导。context/state hashes 一致。

guide-0 的调用要求甚至更具体：直接列出工具名和数值。guide-1 把当前状态、换算值写成自然语言，强调执行加油，但没有新增原先缺少的操作、前提或核验目标。两个版本的生成分析均正确指出“只换算，未实际加油”。因此可观察到表达变化伴随执行变化，无法从中指出某个新补上的关键条件解释成功。

两个 guidance 的 evidence_sha256 不同（attempt-0 `afa3ca...`，attempt-1 `2428e4...`）；具体 actor 起点仍经 request/identity 确认一致。不要将这个案例写成只有一个语义规则被隔离操纵的实验。

首版三个运行均将任务缩减为换算/确认；二版一个运行正确决定执行并调用。二版指导和关键执行正确，但后续未指导思考在看到 20.04 时又猜测容量、称总量“confusing”，最后回复数值正确。因此也不宜称完整思考始终清楚一致。

## 自由文本对比与可保留的研究信息

自由文本指导是正确的完整工具调用，只是没有四字段状态解释；对应 actor 却认为格式化转换值后任务就结束。虽然可提出“状态解释可能更容易让 agent 采取行动”的假设，但当前存档没有把状态解释、格式、措辞、修订预算独立隔离；Teacher 四字段首版同样失败，GPT 更详尽的四字段也有失败。不能把自由文本失败解释成已确认的四字段结构优势。

该案例可另作“正确指导不保证执行，仍需检查实际状态”的观察：guide-0 的局部状态/观测检查为 false，guide-1 为 true，后续请求移除了指导。此时故事重点是检查执行，而不是来源/格式优劣。要作为闭环训练实例，还需复核实际重试调度、反馈生成路径是否与论文协议一致；已保存人工候选试跑不能自动等同于一次在线闭环。

## 建议

1. 当前消融优势案例列表中暂缓 A3，不靠改标题或补防御性说明保留默认 Teacher/GPT 失败对照。
2. 不建议仅改成 Teacher guide-0/guide-1：仍缺少可说明的关键语义修正。
3. 若文章需要“指导质量与执行可靠性不同”这一独立观察，可保留完整证据待另行选用；同一 GPT 指导的两种执行最直接，但它不服务本轮宣传 Teacher 优势的选例目标。
4. 后续选例应寻找基线指导漏掉/误写某个关键约束、执行遵循该错误而失败，Teacher 指导正确指出该约束且执行修复的链条。核验字段的差别也必须在实际检查/后续决策中留下证据。
